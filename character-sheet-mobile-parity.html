Character Sheet — Mobile Parity Plan

Port the recent toon-converter character-sheet work to auto-toon-app. Scope decided per server-side state (what landed vs what's still plan-only on web).

0. What mobile gets for free

Server-side changes shipped on develop are transparent to mobile:

  • Character sheet now merges ref photo + generated panels into one image via sharp. Mobile receives the merged URL unchanged — no client change.
  • Dual billing (face SEEDREAM_4_5 + sheet GPT_IMAGE_2) already happens via two separate API calls mobile already makes (generateFashionModel then generateCharacterSheet). ✅
  • Server-side gates for outdated models (not yet implemented on web) will apply here too when shipped.

1. Post-creation sheet display + download

Current mobile state

app/model-result.tsx already:

  • Calls generateCharacterSheet({ referenceImageUrl, modelName, prompt }) after user confirms save.
  • Stores characterSheetUrl in useModelFactoryStore.savedModels.
  • Shows a SheetTimer while generating.
  • On success: fires an Alert — "Model Saved" — and that's it. Sheet is never shown to the user post-creation.

List screen app/models.tsx renders the sheet thumbnail (line 187), but the user has to navigate back and tap a model to see it.

Proposed flow

  1. After generateCharacterSheet resolves, drop the alert.
  2. Push a new full-screen result modal — app/sheet-result.tsx new — with the merged sheet large, plus action pills:
    • Save to Photos — MediaLibrary.saveToLibraryAsync (already used elsewhere in model-result.tsx).
    • Share — Share.share({ url }).
    • Done — router.replace('/models').
  3. On failure: keep the partial-success alert behavior, but offer a Retry CTA in the same modal.

Reuse the icons + styling from image-viewer.tsx (Save/Share already implemented there — copy the helpers).

2. Outdated models (mobile side)

Tracks the web follow-up plan (character-sheet-followup-plan.html). Server contract:

  • GET /api/fashion-models returns sheetVersion and isOutdated.
  • POST /api/fashion-model/[id]/regenerate-sheet re-runs the sheet for an existing model. Bills GPT_IMAGE_2.
  • POST /api/fashion-editorial/generate returns 409 MODEL_OUTDATED { modelId } if any model is outdated.

Mobile parity work ships after the server contract lands.

3. Dependency / order

  1. Now: §1 post-creation sheet display + download (no server contract dependency).
  2. Web ships §3 of the followup plan: sheetVersion column + regen route + 409 gate.
  3. Then: §2 mobile outdated UI + 409 handling.

4. Risks / notes

  • iOS only-tier behaviors: MediaLibrary.requestPermissionsAsync already wired elsewhere — copy the pattern, don't reinvent.
  • Save-to-Photos with a PNG produced from a 1500+ px wide merged sheet may be large — keep PNG, mobile handles.
  • Avoid auto-regen of outdated models. Always explicit user tap. Show cost on the CTA ("Update · 3 credits").
  • If user has many outdated models, batch not supported in v1 — one at a time.
