Mobile UI · Revamp Plan · 2026-Q2

From “Purple-Glow Soup” to Quiet Editorial

Login + onboarding screens read as premium and inviting. The moment users enter the app, everything turns into a single saturated violet wash with glow halos — content disappears, readability collapses, hierarchy is gone. This plan brings the in-app experience to the same standard as the marketing-side: editorial restraint, content-first contrast, accents used sparingly.

1. What's wrong today

SYMPTOM

Monochromatic violet wash

Every screen background uses #1E1740 → #16102A → #0E0820. Layered with violet glow orbs and a violet/fuchsia accent system. The eye has nowhere to rest. Images on the dashboard fight the background for attention.

SYMPTOM

Low text contrast

Body text at rgba(255,255,255,0.55) against #16102A measures ~4.1:1 — at the AA threshold but feels muddy because the bg already has a purple cast. Small labels (10–11pt) drop below readable.

SYMPTOM

Glow overload

Multiple shadowColor orbs + soft-light blends on every screen. Adds noise without information, kills perceived sharpness of the user's generated images.

SYMPTOM

No content hierarchy

Bento cards, stat bar, gallery, utility row all use the same violet gradient family. Nothing draws the eye first. The dashboard becomes a wall.

2. Design principles for the new look

P1

Content is the hero — not chrome

Backgrounds become near-neutral (warm-black slate). The user's generated photos provide the color. Chrome recedes.

P2

Violet → accent, not foundation

Violet stays for the brand mark and one or two CTAs. Default tone is desaturated. Amber/gold becomes the conversion accent (matches the pay-per-use card from login).

P3

Readability over vibe

Body copy ≥ 14pt at rgba(255,255,255,0.72). Labels at 0.55. AAA on key actions.

P4

One source of light per screen

Kill multi-orb glow stacks. At most one gradient halo, low opacity, behind a single hero element.

P5

Editorial spacing

16/24/40 vertical rhythm. Sections breathe. Cards aren't crammed shoulder-to-shoulder.

P6

Consistent with login

Login screen already uses amber pay-per-use accent + editorial hero. App should feel like the same product — not a violet pivot after sign-in.

3. New color system

Foundation goes warm-slate (almost black). Violet keeps brand identity but only as accent. Amber is the conversion / primary CTA color.

6. Implementation phases

PHASE 1 critical · 1d

Re-tone the theme

Single source-of-truth update. Every screen inherits.

Changes

  • Rewrite constants/theme.ts: bg #0B0F14, bgRaised #131820, bgElevated #1B222D
  • Demote violet from colors.bg tinting — bg becomes neutral warm-slate
  • Promote amber (#FBBF24) to colors.accent; violet (#A78BFA) → colors.accent2 (brand mark / secondary)
  • Replace gradients.pageVignette with flat color — no gradient page bg
  • Update colors.textMuted from 0.55 → 0.72 for body, add textDim 0.48 for labels

7. Risks & non-goals

RISK

Brand-team push-back on "less violet"

Violet stays — it owns the logo, login screens, and one signature gradient. We're not removing it from the brand, we're moving it from everywhere to somewhere.

RISK

Onboarding feels disconnected

Mitigation: Phase 3 hero CTA reuses the same amber-pay-per-use card style from login. Continuity preserved.

NON-GOAL

Light mode

Single dark theme only. iOS/Android dark-mode opt-in is out of scope.

NON-GOAL

Full design-token JSON pipeline

Theme stays a TS module. No Style Dictionary / Figma sync this pass.

8. Rollout

  1. Branch: ui-revamp/phase-1-theme → ship Phase 1+2 first; rest of app inherits 80% of the visual improvement immediately.
  2. Internal review: screenshots of every screen before merging Phase 2. No surprise regressions.
  3. Phase 3–5 in sequence, one PR each — small, reviewable diffs.
  4. Phase 6 sweep after others land.
  5. No feature freeze. Footwear-pack work continues in parallel on a separate branch.

Total est.: 6.5 working days · solo engineer.
